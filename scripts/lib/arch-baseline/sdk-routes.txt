# ⑮ SDK 路由覆盖 —— **债务清单**,⛔ 只许往下走,理想是空的。
#
# 由 scripts/check-sdk-coverage.sh 读取。它回答提案(docs/drafts/
# openapi-chain-proposal.md)的那一句判据在链路最后一环上的形态:
#
#     *一个新端点漏掉 SDK,什么会变红?*
#
# 前面几环已经接上了:⑭b 让「注册了但没注解」变红,⑭c 让「注解了但没注册」变红。
# 这一条让「在 spec 里但没有任何 SDK 暴露它」变红 —— 那是链路上最后一段没人看着的路。
#
# ---------- 格式 ----------
#
#     <class> <METHOD> <path> <理由>
#
# class ∈ exempt | todo
#
#   · `todo`  —— 这个 operation 今天确实没有 SDK 暴露,登记着等人补。
#                 ⛔ 别往这里加新行:基线是历史债的清单,不是新债的收容所。
#   · `exempt` —— 它**不应该**由生成 SDK 暴露,理由写在同一行。
#                 ⚠️ 理由少于 20 个字符会被当成没写(同 ⑭ 的做法):
#                 ⛔ 没有理由的豁免等于关掉检查。
#
# ⚠️ 双向棘轮:一条基线行对应的 operation 从 spec 里消失了,或者它其实已经被
# SDK 暴露了,**这里也红** —— 留着一条对不上的行,等于下次那个端点真掉了 SDK
# 的时候这里不会说话。
#
# ---------- 今天是空的,而那是有意义的 ----------
#
# 两个 SDK 都是**从同一份 spec 生成**的,所以覆盖是由构造保证的:
#   · Go:oapi-codegen 为每个 operation 生成一个 `New<Op>Request` 请求构造器;
#   · TS:openapi-fetch 是泛型客户端,`paths` 类型本身就是 spec 的路径表,
#         spec 里没有的路径是一个**编译错误**。
#
# 也就是说这条门禁真正抓的不是「谁忘了写方法」,而是**「spec 改了,SDK 没重新
# 生成」**(Go 侧的 ⑮② sha256 记录)和**「生成器装死」**(⑮③ 计数)。
# ⛔ 所以这张表只要开始长,就说明有人在手工维护本该生成的东西。
