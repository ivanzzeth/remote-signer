# 由 scripts/check-lint.sh 读取,数字来自 `golangci-lint run`(配置 .golangci.yml)。
#
# ---------- 为什么是计数,不是 file:line 集合 ----------
#
# 本目录里其它棘轮多数用**集合**(arch_ratchet_set),因为每条违规需要一句
# 「为什么它还在」。这一条不能:
#
#   ⛔ errcheck 的发现是 **file:line**。在一个被记录的行**上方**插入任何一行
#      代码,它的行号就变了 —— 于是一次与错误处理毫无关系的改动会同时产生
#      「新增违规」和「基线里有已经不存在的条目」两种红。那种门禁人会绕过。
#      ⚠️ 本目录现有的集合型基线全部是**文件级**或**符号级**(包.结构体.字段、
#      mux pattern),没有一个带行号 —— 不是巧合。
#   ⛔ 退化成文件级集合也不行:那样同一个文件里从 1 处涨到 20 处不会变红。
#
# 所以按**类别 × 位置**切成九档计数。切得细是为了让「档内互相抵消」的空间足够小:
# 一张 331 的总数可以让人在 cmd/ 修掉一条 fmt 输出、同时在 internal/api 丢掉一个
# os.Remove,而门禁一个字都不说。九档之下,那次改动会让两档同时动,两档都红。
#
# ---------- 不在这张表里的两条 ----------
#
#   ⑫a 签名路径上「error 一个字都没接」= **0,硬约束,没有基线**。
#       (唯一那条 `defer resp.Body.Close()` 由 .golangci.yml 的
#        `(io.ReadCloser).Close` 窄排除处理 —— 理由写在那儿。
#        ⚠️ 那条排除**不覆盖** (*os.File).Close 与 (*sql.Rows).Close:
#        daemonize.go:37 和 fk_ensure.go 今天仍被点名,它们算在 offpath_dropped 里。)
#   ⑫c forcetypeassert(`x.(T)` 不带 ok)= **0,硬约束**,全仓今天就是 0。
#
# ---------- 分档的含义 ----------
#
#   dropped  返回的 error **一个字都没接**:`f()`。review 时看不出来。
#   blanked  显式扔掉:`_ = f()` / `v, _ := f()`。至少 review 看得见,但仍然是丢掉。

#            —— 决定「签不签、签什么」的代码。同一类违规在这里更严重。
