# 身份与凭据

**状态**:⛔ **人和钥匙尚未分开** —— 现在「谁」就等于一把钥匙。PRD 的 **D2** 要求
分开,这是本次重构的主要目标之一。

**守的是**:[`prd.md`](../prd.md) 的 **D2**(人钥分离)· **D5**(多管理员)·
**D1**(工作区是边界)· **N7**(凭据与身份不匹配要说得出)· **G5**(收回立即生效)。

**判据**:*这个人离开团队,他做过的事还追得到吗?换一把钥匙会动到别的东西吗?*

**关联**:[`permissions.md`](permissions.md) · [`custody.md`](custody.md) ·
[`../incidents.md`](../incidents.md)。

---

## 1. 现状:一把钥匙就是一个身份

钥匙持有一个公钥、一个角色、一个启用位。授权、签名者归属、审计**全部挂在钥匙上**。

⛔ **后果**:换钥匙 = 换身份。而身份被引用着(授权的归属、签名者的归属),所以
删不掉 —— 于是「钥匙泄露了想换一把」这件事**没有出口**。

**2026-09-10 的真实后果**:管理员密码遗失,唯一可行的办法是**直接改数据库**把公钥
换掉。走受支持的路径(删掉身份重新初始化)会撞上「名下还有东西」的拦阻:15 条授权
和 1 个签名者归属挡着它。原委见 [`../incidents.md`](../incidents.md)。

⭐ **但出口不是「换绑公钥」**(PRD **D13**)。能重新指定某个身份的公钥,按定义就是
一个**完整的账户接管原语** —— 比偷钥匙更省事。

⭐ 成员与钥匙分开之后,这件事**不需要专门的能力**:钥匙丢了就**吊销它、再发一把**,
身份不动。所谓「换钥匙不换身份」就是一个普通操作,不是恢复流程。

⛔ **代价必须说清**:一个成员的钥匙**全部**丢失时,产品内**无法恢复**。只能由拥有
那台机器访问权的人处理 —— 这是刻意的,任何产品内的恢复路径都是攻击面。

## 2. 归属由三处各自表达

| 表达 | 说的是 |
|---|---|
| 授权的归属 | 这条授权是谁的 |
| 授权作用于谁 | 它在哪些身份的请求上生效 |
| 签名者的归属 | 这个地址是谁的 |

⛔ **三者必须一致,但没有任何机制保证一致。** 三处说法不一时以哪个为准 —— 现在
答不上来。这是重构要收敛的第二件事。

## 3. 认证

请求带签名与一次性随机数,服务端验签并防重放。⚠️ 时间戳有窗口,过老的请求被拒。

⛔ **认证失败必须分两种结论**(N7):

| 结论 | 主人该做什么 |
|---|---|
| **你不是他** —— 签名验不过 | 检查钥匙和身份是否配对 |
| 你是他,但**不许做这件事** | 检查角色与范围 |

**2026-09-10 的真实后果**:界面接受了「钥匙 A + 身份 B」的组合、加密存下、放人进
后台,然后**每个页面都报「没有权限」** —— 而那句话把人引向角色配置,那里什么问题
都没有。更糟的是那段代码有一句注释声称它会先验证,而它从不询问服务端。

## 4. 目标形状

| | |
|---|---|
| **成员** | 身份(人或 agent),工作区的成员 |
| **钥匙** | 凭据,**属于**某个成员,一人可多把 |

- 换钥匙不动成员的名字、名下授权、签过的东西
- 钥匙全部吊销后,这个成员做过的事仍查得到、仍记在他名下
- 成员可**停用**而不删除 —— 删除会断掉追责链
- 一个工作区可以有多个管理员(D5)

## 5. 重构时必须保住的

- [ ] 认证失败分「你不是他」与「不许做这件事」
- [ ] 收回授权立即生效,不需要重启(G5)
- [ ] 防重放与时间窗
- [ ] **目标**:成员与钥匙分离 —— 一人多钥,吊销一把不影响其它
- [ ] ⛔ **不做**:找回/换绑凭据的口子(D13)
- [ ] **目标**:三处归属收敛成一处,或明确谁是权威
- [ ] **目标**:每条数据带工作区标识,过滤发生在取数层(D1 / D6)
