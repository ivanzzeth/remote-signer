# 规则判定

**状态**:已实现。两层判定(黑名单 → 白名单)+ 委托链 + 额度,八个判定器注册在册。

**守的是**:[`prd.md`](../prd.md) 的 **G2**(默认拒绝)· **G4**(答得出是哪条授权
放行的)· **G6**(说不清就拒绝)· **N6**(拒绝要说得出是哪一条、缺什么)·
**G7**(不能自我提权)。

**判据**:*这一条改了,上面哪条保证会不成立?* 答不上来,它就是实现细节,不该写在这。

## 1. 判定顺序,以及每一道门失败的方向

```
黑名单 ─── 命中 ──► 拒绝
   │  ⛔ 出错也拒绝
   ▼
白名单 ─── 命中 ──► 放行 → 额度 → 签名
   │  ⚠️ 出错跳过这条,继续下一条
   ▼
都不命中 ──► 等人批准
```

⛔ **两道门的失败方向相反,这是设计不是疏忽:**

| 门 | 出错时 | 为什么不能反过来 |
|---|---|---|
| 黑名单 | **拒绝全部** | 一条本该拦东西的规则算不出结论时放行,等于攻击者只要让它崩就能绕过 |
| 白名单 | **跳过这条** | 一条坏的白名单不该拖垮其它有效白名单 |

⚠️ **黑名单 fail-closed 的代价必须被看见。** 2026-09-10:一条黑名单规则依赖当时
环境里没有的判定引擎,于是**每一笔签名都被拒**,而报出来的只有「等待批准超时」。
十一项验证失败,没有一项提到那条规则或那个引擎。详见
[`../incidents.md`](../incidents.md)。⛔ 这就是 N6 的由来 —— fail-closed 是对的,
说不出理由的 fail-closed 等于停摆,而停摆和被攻击在主人眼里长得一样。

## 2. 判定器是注册进来的,不是分发出去的

调用方**不问**「这条规则该用哪个判定器」,它问判定器「你处理哪一种」。

| 形状 | 为什么 |
|---|---|
| 判定器声明自己处理的类型,注册进表 | 加一个引擎不该需要改任何调用点 |
| 服务开始收请求后封表 | 运行中注册 = 判定集合会变,而变化时刻无人知道 |
| 类型清单只有一份,其余全部派生 | ⛔ 曾经有七份手写副本,其中一份漏了一个已注册的引擎,导致**没有人能创建那种规则**——引擎接线完整却无法抵达 |

## 3. 委托链

一条规则可以把内层载荷交给另一条规则判定(拆 Safe / MultiSend 这类包装)。

| 约束 | 为什么 |
|---|---|
| 深度上限 | 攻击者可影响的输入上无界递归 = 拒绝服务 |
| 环检测 | 同上 |
| ⛔ **内层载荷重跑黑名单** | 否则包一层就能绕过黑名单 —— 这是委托最容易被利用的地方 |

⚠️ 遍历实现**只能有一份**。2026-09-10 曾有三份,其中一份把「配置解析失败」读成
「不委托」,于是隔离判定跳过整条委托链,给出一个**假的通过**。

## 4. 规则的两种形态

规则的配置以**模板形态**存储(含未展开的变量),在判定时才成为**解析形态**。

⛔ 拿模板形态去做「这条规则合法吗」的校验,会把所有实例规则判成非法 —— 因为
`${变量}` 不是一个合法地址。校验必须针对解析形态。

⚠️ 这两种形态在类型上目前**没有区别**,靠调用方记得用哪一个。这是
[`../../ARCHITECTURE.md`](../../ARCHITECTURE.md) 想消掉的形状之一。

## 5. 写入收口

所有规则写入走同一个入口,那里做校验。⛔ 绕开它直接写库的路径必须为零 —— 有一条
就意味着「所有规则都被校验过」这句话不成立,而它是 G4 的前提。

⚠️ 一个例外是设计好的:**只改元数据(启用/停用)的写入不做校验**。否则一条已经
损坏的规则**连关都关不掉** —— 那是 fail-closed 用错了方向,把主人锁在门外。

## 6. 重构时必须保住的

- [ ] 黑名单 fail-closed、白名单 fail-open,方向不能对调
- [ ] 拒绝时说得出**是哪一条**、缺什么(N6,目前不成立)
- [ ] 委托内层重跑黑名单
- [ ] 深度上限与环检测
- [ ] 类型清单单一来源
- [ ] 写入单一入口,元数据写入是唯一例外
