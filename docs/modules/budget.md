## 1. ⛔ 三个上限字段,「无限」都用同一个值表示

| 字段 | 什么值等于不限额 |
|---|---|
| 总额 | 空字符串、`-1` |
| 单笔 | 同上 |
| 笔数 | `<= 0`(判定写在取数条件里) |

⛔ **这就是 N1 的根源**:未设置、不限额、算不出来 —— 三种语义挤在一个字段里,而其中
**三种都落在宽松那一侧**,零值恰好也是最宽松的那个。

**2026-09-10 的真实后果**:模板里的上限可以引用变量,变量名**拼错一个字母**时,
产品既不报错也不拒绝,而是把那条上限当成「不限额」。出厂的 agent 模板里有 **6 处**
上限是这么写的。原委见 [`../incidents.md`](../incidents.md)。

现在:**算不出上限一律报错**,四条路径全部 fail-closed —— 求值时拒签、启动时拒绝
启动、接口返回错误并点名是哪个变量、校验时提前发现。

⚠️ 只管上限字段。小数位、告警比例这些**不是限额**,它们的 `-1` 仍是正确的「未设置」。

## 2. 计量单位是个有内部结构的字符串

形如 `<链>:<代币>`。⛔ 有五个以上的函数在解析、拼接、比较、格式化它 —— 一个有内部
结构的键被当成不透明字符串传递,是 [`../../ARCHITECTURE.md`](../../ARCHITECTURE.md)
想消掉的形状之一。

⚠️ 单位里的变量必须在**记账前**解析。未解析的 `${代币地址}` 意味着**支出记在一行,
而上限挂在另一行** —— 两边都对不上,于是谁也没限住谁。

## 3. 扣减必须是原子的

判定「够不够」和「扣掉」之间如果有缝,并发请求就能同时通过。⛔ 实现上是一条带条件
的更新:条件不满足则零行受影响,而不是先读后写。

## 4. 动态额度

判定逻辑可以在运行时决定这一笔算在哪个单位上(例如按代币)。

⛔ **必须有「最多多少个不同单位」的上限**。没有它,攻击者换 N 种代币就得到
N × 单笔上限的实际额度 —— 每一笔都在自己的单位里合规。

## 5. 周期

上限可以是「每天」「每月」或「一直」。⚠️ 续期判断出错时 **fail-closed**:陈旧的额度
数据会让人花掉上一周期已经用掉的份额。

## 6. 重构时必须保住的

- [ ] 算不出上限 = 不许花钱(四条路径都要,不只是求值时)
- [ ] 扣减原子,判定与扣减之间没有缝
- [ ] 动态额度有「不同单位数量」上限
- [ ] 周期续期出错时拒绝
- [ ] 单位在记账前完成解析
- [ ] **目标**:四个挂载点、全部同时生效、取最严 —— 新增一条授权只能多一道闸
