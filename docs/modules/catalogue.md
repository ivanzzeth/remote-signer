# 授权目录:模板 · 预设 · 实例

**状态**:已实现。模板与预设从磁盘目录加载,应用后展开成实例授权。

**守的是**:[`prd.md`](../prd.md) 的 **§5.2**(可组合性)· **§5.4**(跨链)·
**N5**(看得出实际允许什么)· **N2**(不许部分生效)。

**判据**:*主人看到的这条授权,和实际生效的是同一个东西吗?*

**关联**:[`rule-engine.md`](rule-engine.md) · [`budget.md`](budget.md) ·

## 1. 三层:模板 → 预设 → 实例

| | 是什么 |
|---|---|
| **模板** | 协议的判定逻辑,带变量声明 |
| **预设** | 某个场景的组合:填哪些变量、用哪几个模板 |
| **实例** | 应用后真正生效的那条授权 |

## 2. ⛔ 变量有四个阶段,每个阶段都可能丢东西

```
模板声明的默认值 → 预设填的值 → 应用时传的值 → 求值时补默认
```

⚠️ **部分更新必须是合并,不是替换**。只传一个变量就把其它的抹掉,会让本来有上限的
授权变成没上限 —— 这是 N2「不许部分生效」在这一层的样子。

⛔ **`${变量}` 的展开只能有一份实现。** 曾经有五份,它们对同一个写法的理解不一致,
于是**应用时和求值时对同一条授权的判断不同** —— 主人看到的和实际生效的不是一个东西
(N5)。

⚠️ 变量的约束(取值范围、可选项、上下界)曾经**声明了但无人执行** —— 注释写着
「校验器要求…」,而全树没有一处读它。现在在应用时执行,并且校验会提前发现「默认值
违反它自己声明的约束」。

## 3. 目录来自磁盘,同步是「补齐 + 剪除」

目录同步会**删掉**源里已经不存在的行。⛔ 剪除必须限定在「这个来源的行」——否则一个
来源的同步会删掉另一个来源的东西。

⚠️ 同一份文件格式曾被多个结构体各解析一份,字段集不一致。其中一处让
「`enabled: false` 的模板照样被注册」—— 一个**故意关掉的模板仍然生效**。

## 3.5 编写入口是 agent

内置条件**只服务机器生成**(PRD **D14**):批准一笔请求后自动记住的那条规则用它们,
人读它们来理解机器写了什么。⛔ 它们不是给人拼的积木。

⚠️ 人写不出来时,让 agent 照 `skills/remote-signer-rule-development` 写。这意味着
**批准的人不是写的人** —— N5(看得出这条授权实际允许什么)是这条路径唯一的刹车,
所以校验、测试用例、以及「实际生效的和显示的是同一个东西」都不是可选项。

## 4. 跨链

**一条策略 × 多条链**(PRD **D15**)。现在按链覆盖的是**变量**;差异只在参数时够用。

⛔ **逻辑也不同时,重写必须限定在具名部分。** 能整体替换就等于 N 条策略套在一个
文件里 —— 漂移一点没少,只是看不见了。判据:*读这一条策略,答得出「哪几条链不一样、
不一样在哪」吗?*

⚠️ 判据二:*新增一条链要改几个地方?* 大于 1 就说明模型不对。

## 5. ⛔ 一条授权的「名字」是引用键

从配置加载的模板,它在配置里的名字是**实例授权引用它的键**。文件自己的 `name:` 不
能覆盖它 —— 覆盖会让每一条引用它的授权**找不到目标**。

⚠️ 这一点曾被一句错误的注释误导(「文件自己的元数据 downstream 会赢」),照着改之后
端到端验证当场红。

## 6. 重构时必须保住的

- [ ] 变量部分更新是合并,不是替换
- [ ] `${变量}` 展开只有一份实现
- [ ] 变量约束在应用时被执行;默认值也要过自己的约束
- [ ] 目录剪除限定在本来源
- [ ] 文件格式只有一个结构体,其余别名
- [ ] 引用键不被文件内容覆盖
- [ ] 内置条件服务机器生成;不做拼装界面(D14)
- [ ] 机器/agent 写的规则必须可复核:校验、测试用例、显示与实际一致
- [ ] **目标**:按链重写**逻辑**(现在只能重写变量),且限定在具名部分
- [ ] 新增一条链只改一处
