# 产品需求(PRD)

**用途**:说清**这个产品要为谁解决什么问题**、必须给出什么保证。架构、模块设计、
代码都从这里反推 —— 反过来不行。

**判据**:*这句话换一套完全不同的实现,还成立吗?* 不成立 = 它是架构决策,不是
产品需求,请挪到 [`../ARCHITECTURE.md`](../ARCHITECTURE.md) 或模块文档。

**关联**:[`../ARCHITECTURE.md`](../ARCHITECTURE.md)(系统应该长什么样) ·
[`../SECURITY.md`](../SECURITY.md)(威胁模型)。

---

## 0. 约定

### 0.1 这份文档里不写技术

⛔ 不出现类型、函数、文件路径、接口、库名、数据库、协议细节。出现了就是串层了。

⚠️ 但**产品词汇**要用准:主人在界面和命令行里看得见的东西 —— 签名请求、规则、
黑名单/白名单、额度、模板、预设、API key、角色、链 —— 都是产品概念,不是技术。

### 0.2 「待决策」是一等公民

⛔ 我说不清的事不许替你编一个答案填进去。拿不准的一律进 §7,写清**选项和代价**。
一份看起来完整、其实有一半是猜的 PRD,比一份明说「这里没定」的更贵 —— 因为后者
会被讨论,前者会被当成已决策照着建。

---

## 1. 这个产品解决什么问题

一个自动化程序要在链上花钱。**把私钥给它,等于把全部权力给它** —— 它写错一行、
被人诱导、或者被攻破,损失就是账户里的全部。

这个产品的存在,是为了让主人**把恰好那么多权力交出去**:说清「允许做什么、最多
花多少、到什么时候为止」,然后即使那个程序完全不受控,边界依然成立。

⚠️ 威胁不只是「密钥被偷」。更常见的是**我自己写的 agent 做了我没打算让它做的事**
—— 逻辑 bug、上游数据被污染、或者它读到的网页里藏了一句指令。产品必须假设
**请求方本身不可信**,而不只是防外人。

---

## 2. 谁在用它

| 画像 | 他要什么 | 成功长什么样 |
|---|---|---|
| **P1 资金主人** | 把权力交出去,但交得清楚 | 睡得着;第二天早上看得懂钱花在哪 |
| **P2 自动化 agent** | 干活时不要卡住 | 该它能干的事不用等人;不该它干的事拿不到签名 |
| **P3 集成开发者** | 把应用接上去 | 一次接好,不用为每条链/每个协议重来 |
| **P4 组织** | 多人多 agent 共用一套资产与授权 | 换人、退役 agent 不影响别人;责任说得清 |

⛔ **P4 目前表达不出来。** 现在「谁」等于一把 API key —— 没有「组织」这个概念,
所以「同一个组织里的两把钥匙」和「两个陌生人」在产品上是一样的。详见 §5.3、§7。

---

## 3. 关键旅途

一条旅途断在第几步,就是产品缺口的位置。⚠️ 描述断点要具体到**主人当时看到什么**。

| # | 旅途 | 现在的状态 |
|---|---|---|
| **J1** | 主人第一次给 agent 授权,到 agent 签出第一笔 | 可走通 |
| **J2** | agent 撞到没授权过的操作,自己解开或求助 | 可走通,但**主人要理解一套概念才能救** |
| **J3** | 主人收紧或放宽一条已有授权 | 可走通 |
| **J4** | 主人想知道「这个月花了多少、花在哪」 | **只能按单条授权看,汇不出总数**(§5.1) |
| **J5** | 出事了,主人要立刻停掉某个 agent | 可走通 |
| **J6** | 同一套授权用到一条新的链 | 可走通,但**要改配置而不是加一行**(§5.4) |
| **J7** | 组织里换人 / 某个 agent 退役 | **表达不出来**(§5.3) |

---

## 4. 必须成立的保证

这些是**对主人的承诺**。任何一条不成立都是严重缺陷,不是待办。

| # | 保证 |
|---|---|
| **G1** | 私钥不离开这个服务。任何人、任何接口都拿不到它 |
| **G2** | **默认拒绝**。没有被明确允许的事,不会被签 |
| **G3** | 授权带上限。上限用完就停,不需要人在场 |
| **G4** | 每一次签名都答得出「是哪一条授权允许了它」 |
| **G5** | 主人随时能收回授权,**立即生效**,不用重启 |
| **G6** | **说不清就拒绝**。任何一处判断不出结论,结果一律是拒绝,而不是放行 |
| **G7** | agent **不能扩大自己的授权**。它可以申请,批准必须由人做 |

⭐ **G6 是这份文档里最贵的一条。** 它不是「小心一点」的意思,而是:*当配置写错、
数据缺失、或者哪一步算不出来时,产品的行为必须是「不签」*。已经出过一次代价很高
的反例 —— 见 §6。

---

## 5. 必须能表达的东西

### 5.1 花多少钱

**现在能表达**:某条授权、在某个币上、每个周期最多花多少、单笔最多多少、最多多少笔。

**表达不出来的**:

| 缺口 | 主人实际会问的话 |
|---|---|
| **跨币种总额** | 「这个 agent 一天最多动 100 美元,**不管什么币**」 |
| **跨授权总额** | 「我给了它 5 条授权,加起来一个月不超过 1000」 |
| **组织总额** | 「整个团队这个月的链上支出上限」 |
| **汇总视图** | 「这个月一共花了多少」——现在只能一条一条看 |

⚠️ 根子在于:**额度现在是挂在「一条授权 + 一个币」上的,而主人心里的额度是挂在
「谁」和「一段时间」上的**。这两个不是同一个东西,产品需要后者。

⛔ 不能用「多加几条授权」绕过去 —— 那样上限会**相加**,而主人要的是**封顶**。

### 5.2 允许做什么

**现在能表达**:一条授权说清「在哪条链、对哪个合约、调哪个方法、参数满足什么条件」。
复杂条件可以自己写判断逻辑。也提供了一批现成的模板。

**要回答的问题**:现成的东西**够不够搭**?

⚠️ 观察到的现象:出厂目录里 **44 条**规则是「自己写判断逻辑」,而各类内置条件
每种只用到 **1–2 次**。这说明实际的组合发生在「自己写」那一层,内置的那批**没有
被当成积木用**。

这可能有两种解读,需要 §7 定:内置条件的粒度不对(拆得不够细,拼不出想要的),
或者它们本来就只是给机器生成用的、不该指望人来拼。

### 5.3 谁能做什么

**现在能表达**:四种角色(管理员 / 开发 / agent / 策略)· 每条授权有归属 ·
每条授权指定它作用于哪些钥匙 · 每个链上地址有归属。

**表达不出来的**:

| 缺口 | 后果 |
|---|---|
| **没有「组织」** | 「同组织的两把钥匙」和「两个陌生人」一样,P4 无法表达 |
| **人和钥匙是一回事** | 换人 = 换钥匙 = 那个人做过的事全部改归属,追责链断掉 |
| **角色是固定四种** | 「只能看不能动」「只能动这一个协议」表达不出来 |
| **退役没有流程** | agent 不再用了,它的授权和历史怎么办,产品没说 |

⚠️ **归属现在由三处各自表达**(授权的归属、授权作用于谁、地址的归属),它们必须
互相一致,但产品上没有一个地方**保证**它们一致。三处说法不一时,以哪个为准 ——
现在答不上来。

### 5.4 在哪条链上

**现在能表达**:一条授权可以绑定一条链,也可以给一张「每条链各自的参数表」。

**缺口**:主人心里的东西是「**这一条策略,在这几条链上都算数**」,而现在要表达成
「一条授权 + 一张按链分行的参数表」。链多了以后,那张表是要维护的东西,而不是自动
成立的事实。

⛔ 判据:*新增一条链,主人要改几个地方?* 大于 1 就说明模型不对。

## 6. 必须不可能发生的事

⭐ 这一节和 §4 的区别:§4 是「产品保证会做到」,这一节是「**主人想配错都配不出来**」。
前者靠正确实现,后者靠产品形状本身。

| # | 不许发生 | 为什么写在这里 |
|---|---|---|
| **N1** | 配置写错,结果比写对**更宽松** | 见下方真实案例 |
| **N2** | 一条授权**部分生效** | 要么整条算数,要么整条不算数。半生效的授权没人能推理 |
| **N3** | 「没设置」被当成「不限制」 | 空着不填的后果必须是**更严**,不是更松 |
| **N4** | agent 通过任何路径给自己加权限 | 包括「改模板」「改参数」这类间接路径 |
| **N5** | 主人看不出某条授权**实际**允许什么 | 界面上显示的和实际生效的必须是同一个东西 |

### N1 的真实案例(2026-09-10 修复)

主人在模板里写额度上限时,可以引用一个变量。**如果那个变量名拼错了一个字母** ——
产品既不报错,也不拒绝,而是把这条上限当成「**不限额**」。

主人以为自己设了上限,界面上也确实写着有上限,而实际上那条授权可以花光账户。
出厂的 agent 模板里有 **6 处**上限是这么写的。

⛔ 这就是 N1 说的形状:**一个拼写错误,让结果变得更宽松**。修的时候不能只修这一个
变量,要让「算不出上限」这件事在产品上等于「不许花钱」。

## 7. 待决策

⛔ 这些只有你能定。定之前不要往下反推架构 —— 否则架构会替你把它们默认掉。

| # | 决策 | 选项与代价 |
|---|---|---|
| **D1** | 「组织」要不要成为一等概念 | 要:P4/J7 成立,但身份模型要重做,已有部署要迁移。不要:多租户永远靠约定 |
| **D2** | 人和钥匙要不要分开 | 分开:换人不断追责链,但多一层概念。不分:J7 断在第一步 |
| **D3** | 额度挂在「谁 + 一段时间」上,还是继续挂在「一条授权 + 一个币」上 | 前者能表达 §5.1 全部缺口,但和现有额度语义不兼容 |
| **D4** | 角色固定四种,还是可以自己组合权限 | 固定:简单、不会配错。可组合:表达力够,但主人会配出自己也说不清的组合 |
| **D5** | 内置条件是给人拼的,还是只给机器生成用 | 决定 §5.2 是「把内置条件拆细」还是「承认自己写才是主路径」 |
| **D6** | 跨链策略是「一条策略 × 多条链」还是「每条链一条策略」 | 前者新增链只改一处,但「这条链上参数不一样」要另想办法 |
| **D7** | 出事时的最小动作是什么 | 现在是「停掉一个 agent」。要不要有「全局暂停」这种一键动作 |

---

## 8. 不在范围内

⚠️ 明确写出来,免得被当成遗漏:

- **不做资产管理**:不负责换币、不负责路由、不给投资建议。
- **不做链上数据服务**:不承诺提供历史、行情、索引。
- **不替主人判断一笔交易划不划算**:只判断它**是否在授权范围内**。
