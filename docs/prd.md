# 产品需求(PRD)

**用途**:说清**这个产品要为谁解决什么问题**、必须给出什么保证。架构、模块设计、
代码都从这里反推 —— 反过来不行。

**判据**:*这句话换一套完全不同的实现,还成立吗?* 不成立 = 它是架构决策,不是
产品需求,请挪到 [`../ARCHITECTURE.md`](../ARCHITECTURE.md) 或模块文档。

**关联**:[`../ARCHITECTURE.md`](../ARCHITECTURE.md)(系统应该长什么样) ·
[`../SECURITY.md`](../SECURITY.md)(威胁模型)。

---

## 0. 约定

### 0.1 这份文档里不写技术

⛔ 不出现类型、函数、文件路径、接口、库名、数据库、协议细节。⚠️ 但**产品词汇**
要用准:主人在界面和命令行里看得见的东西(签名请求、规则、黑名单/白名单、额度、
模板、预设、钥匙、角色、链)都是产品概念,不是技术。

### 0.2 「待决策」是一等公民

⛔ 说不清的事不许编答案。拿不准的进「待决策」并写清代价 —— 看起来完整而有一半是猜的 PRD 比明说「没定」的更贵:后者会被讨论,前者会被照着建。

---

## 1. 这个产品解决什么问题

一个自动化程序要在链上花钱。**把私钥给它 = 把全部权力给它** —— 它写错一行、被人
诱导、或被攻破,损失就是账户里的全部。

这个产品的存在,是为了让主人**把恰好那么多权力交出去**:说清「允许做什么、最多
花多少、到什么时候为止」,然后即使那个程序完全不受控,边界依然成立。

⚠️ 威胁不只是「密钥被偷」。更常见的是**我自己写的 agent 做了我没打算让它做的事**
—— 逻辑 bug、上游数据被污染、或它读到的网页里藏了一句指令。产品必须假设**请求方
本身不可信**,而不只是防外人。

---

## 2. 谁在用它

| 画像 | 他要什么 | 成功长什么样 |
|---|---|---|
| **P1 资金主人** | 把权力交出去,但交得清楚 | 睡得着;第二天早上看得懂钱花在哪 |
| **P2 自动化 agent** | 干活时不要卡住 | 该它能干的事不用等人;不该它干的事拿不到签名 |
| **P3 集成开发者** | 把应用接上去 | 一次接好,不用为每条链/每个协议重来 |
| **P4 团队** | 多人多 agent 共用一套资产与授权 | 换人、退役 agent 不影响别人;责任说得清 |

⭐ P4 由**工作区**承载(§5.3)。⚠️ 本地/开源部署**有且只有一个工作区,而且主人
永远不需要知道它存在** —— 界面上不出现、配置里不用填。它对单机用户是隐形的。

## 3. 关键旅途

一条旅途断在第几步,就是产品缺口的位置。⚠️ 断点要具体到**主人当时看到什么**。
| # | 旅途 | 现在的状态 |
|---|---|---|
| **J1** | 主人第一次给 agent 授权,到 agent 签出第一笔 | 可走通 |
| **J2** | agent 撞到没授权过的操作,自己解开或求助 | 可走通,但**主人要理解一套概念才能救** |
| **J3** | 主人收紧或放宽一条已有授权 | 可走通 |
| **J4** | 主人想知道「这个月花了多少、花在哪」 | **只能按单条授权看,汇不出总数**(§5.1) |
| **J5** | 出事了,主人要立刻停掉某个 agent | 可走通 |
| **J6** | 同一套授权用到一条新的链 | 可走通,但**要改配置而不是加一行**(§5.4) |
| **J7** | 团队里换人 / 某个 agent 退役 | 目标形状已定(§5.3),**尚未实现** |
| **J8** | 同一人管着两台(本机 + 生产),要切过去 | **表达不出来**:没有 profile,切后端等于重输身份([`product-forms.md`](product-forms.md)) |

## 4. 必须成立的保证

这些是**对主人的承诺**。任何一条不成立都是严重缺陷,不是待办。

| # | 保证 |
|---|---|
| **G1** | 私钥不离开这个服务。任何人、任何接口都拿不到它 |
| **G2** | **默认拒绝**。没有被明确允许的事,不会被签 |
| **G3** | 授权带上限。上限用完就停,不需要人在场 |
| **G4** | 每一次签名都答得出「是哪一条授权允许了它」 |
| **G5** | 主人随时能收回授权,**立即生效**,不用重启 |
| **G6** | **说不清就拒绝**。任何一处判断不出结论,结果一律是拒绝,而不是放行 |
| **G7** | 任何身份都**不能扩大自己的授权**。可以申请,批准必须由人做 |

⛔ **G7 曾只对 agent 成立**,「开发」档能自建放行授权且免审批 —— **D11 删掉那一档即消除**。见 [`incidents.md`](incidents.md)。

⭐ **G6 最贵。** 不是「小心一点」的意思,而是:*配置写错、数据缺失、哪一步算不出
结论时,产品的行为必须是「不签」*。已经出过一次代价很高的反例 —— 见 §6。

## 5. 必须能表达的东西

### 5.1 花多少钱

**现在能表达**:某条授权、在某个币上、每个周期最多花多少、单笔最多多少、最多多少笔。

**表达不出来的**:

| 缺口 | 主人实际会问的话 |
|---|---|
| **跨币种总额** | 「这个 agent 一天最多动 100 美元,**不管什么币**」 |
| **跨授权总额** | 「我给了它 5 条授权,加起来一个月不超过 1000」 |
| **组织总额** | 「整个团队这个月的链上支出上限」 |
| **汇总视图** | 「这个月一共花了多少」——现在只能一条一条看 |

⚠️ 根子在于:**额度现在是挂在「一条授权 + 一个币」上的,而主人心里的额度是挂在
「谁」和「一段时间」上的**。这两个不是同一个东西,产品需要后者。

**目标形状**:额度可以挂在四个位置上 —— 工作区、成员、钥匙、单条授权。

| 规则 | 说明 |
|---|---|
| **全部同时生效** | 一笔支出要同时过掉它撞上的每一个上限 |
| **取最严的那个** | 有效额度是所有适用上限里最小的 |
| 每个上限有**周期** | 「一天」「一个月」「一直」由主人选 |

⛔ 这条规则是「多加几条授权就能提高上限」这件事**在产品上不成立**的原因:
新增一条授权只会**多一道闸**,不可能松开已有的任何一道。

⚠️ 「不管什么币」需要一个共同计价单位,而引入计价来源就是引入一个新的信任假设
和一个新的故障模式。⛔ 按 G6,**报价拿不到时必须拒签**,不能按「暂时不限额」放行。
计价怎么来 —— 见 §8/D3。

### 5.2 允许做什么

**现在能表达**:一条授权说清「在哪条链、对哪个合约、调哪个方法、参数满足什么条件」。
复杂条件可以自己写判断逻辑。也提供了一批现成的模板。

**要回答的问题**:现成的东西**够不够搭**?

⚠️ 观察到的现象:出厂目录里 **44 条**规则是「自己写判断逻辑」,而各类内置条件
每种只用到 **1–2 次**。这说明实际的组合发生在「自己写」那一层,内置的那批**没有
被当成积木用**。

两种解读,见 §8/D7:内置条件粒度不对(拼不出想要的),或者它们本就只给机器生成
用、不该指望人来拼。

### 5.3 谁能做什么

#### 工作区

**工作区**是边界:钥匙、授权、额度、成员、审计都属于某一个工作区,不跨越它。

| 规则 | 说明 |
|---|---|
| 一个部署**至少**有一个工作区 | 本地/开源部署就只有这一个,且**对主人隐形** |
| 越界的东西**看起来不存在** | 不是「你没权限」,而是「没有这个东西」。前者泄露了它的存在 |
| 默认工作区是**迁移锚点** | 既有单机部署接上多工作区时,原有数据直接成为它的数据,不迁移;它默认**没有成员** —— 是老数据的落脚点,不是新人的 |

⛔ 多工作区**不做在开源层**。开源层只需要保证:工作区这个边界从第一天就在,
所以将来打开多工作区不是一次迁移,而是一个开关。

#### 人、钥匙、agent

⭐ **人和钥匙是两个东西**(已决策,§7)。

| 概念 | 是什么 | 换掉它会怎样 |
|---|---|---|
| **成员** | 一个人,或一个 agent。工作区的成员 | 人走了,他做过的事仍然记在他名下 |
| **钥匙** | 一次访问凭据,**属于某个成员** | 钥匙泄露就换钥匙,不影响这个成员的身份和历史 |

**必须能做到**:

- **换钥匙不换身份**。钥匙丢了或泄露了,换一把,而这个成员的名字、名下的授权、
  签过的东西**全都不动**。⚠️ 目前做不到:只能删掉身份重建,而那会撞上「名下还有
  东西」这道拦阻 —— 于是唯一的出路是直接改数据库。见 [`incidents.md`](incidents.md)。
- 一个成员可以有多把钥匙(不同机器、不同用途),吊销一把不影响其它。
- 钥匙全部吊销后,这个成员做过的事**仍然查得到、仍然记在他名下**。
- 一个工作区可以有**多个管理员** —— 单点管理员是单点故障,也是单点风险。
- 成员可以被停用而不被删除。⛔ 删除会断掉追责链,停用不会。

**基本成员管理**:邀请 / 移除 / 停用 / 改角色 / 看谁有哪些钥匙。

⚠️ 角色怎么分见 §8/D4。已知约束:「拥有」(转让、删工作区)和「日常能做什么」不是
一根轴,挤进一根会逼出「为了删东西而给全权」。

### 5.4 在哪条链上

**现在能表达**:一条授权可以绑定一条链,也可以给一张「每条链各自的参数表」。

**缺口**:主人心里的东西是「**这一条策略,在这几条链上都算数**」,而现在要表达成
「一条授权 + 一张按链分行的参数表」。链多了以后,那张表是要维护的东西,而不是自动
成立的事实。

⛔ 判据:*新增一条链,主人要改几个地方?* 大于 1 就说明模型不对。

## 6. 必须不可能发生的事

⭐ 这一节和 §4 的区别:§4 是「产品保证会做到」,这一节是「**主人想配错都配不出来**」。
前者靠正确实现,后者靠产品形状本身。

| # | 不许发生 | 为什么写在这里 |
|---|---|---|
| **N1** | 配置写错,结果比写对**更宽松** | 见下方真实案例 |
| **N2** | 一条授权**部分生效** | 要么整条算数,要么整条不算数。半生效的授权没人能推理 |
| **N3** | 「没设置」被当成「不限制」 | 空着不填的后果必须是**更严**,不是更松 |
| **N4** | agent 通过任何路径给自己加权限 | 包括「改模板」「改参数」这类间接路径 |
| **N5** | 主人看不出某条授权**实际**允许什么 | 界面上显示的和实际生效的必须是同一个东西 |
| **N6** | 拒签时说不出**是哪一条授权拒的、缺什么** | 见下方 2026-09-10 的第二个案例 |
| **N7** | 凭据和身份不匹配时,**无从得知** | 见下方 2026-09-10 的第三个案例 |

这三条都不是设想出来的 —— 每一条都有一次真实事故,记在
[`incidents.md`](incidents.md)。⚠️ 读那份文档不是为了追责,是因为**一条不许发生的
事,只有在它发生过之后才写得准**。

## 7. 已决策

⭐ 决策记在这里,连同**它排除了什么**。只写结论、不写为什么排除,下一个人会把
排除掉的选项重新想一遍。

| # | 决策(2026-09-10) | 它排除了什么 |
|---|---|---|
| **D1** | **工作区**是边界,但**多工作区不做在开源层**。开源部署只有一个,且对主人隐形 | 排除了「以后再加租户」——那会是一次迁移。边界从第一天就在,打开它只是开关 |
| **D2** | **人和钥匙分开**。成员是身份,钥匙是凭据,一个成员可有多把 | 排除了「换人 = 换钥匙」,那会让追责链在每次人员变动时断掉 |
| **D5** | 一个工作区可以有**多个管理员** | 排除了单点管理员 —— 那既是单点故障也是单点风险 |
| **D6** | 越权的东西**表现为不存在**,不是「无权限」 | 排除了「403」——它确认了那个东西存在,本身就是泄露 |
| **D3** | 跨币种封顶**暂时不做** | 排除了引入报价来源 —— 那会带来一个新的信任假设,且按 G6「报价拿不到必须拒签」,报价源抖动会停掉**全部**签名。代价:§5.1 第一条缺口留着,额度只能按币种分设 |
| **D11** | **删掉「开发」这一档**。本地开发用管理员 + 临时数据目录 | 排除了「半可信身份」—— 一个说不清能做什么的档,最后总会被当成「差不多是管理员」。⛔ 同时消掉了 G7 只成立一半的那条路径 |
| **D12** | **默认生产**。开发环境须**显式指定**且**显式给数据目录** | 排除了「不小心跑在开发模式」和「开发环境写坏真数据」。⛔ 它只隔离**数据**不放松**策略** —— 放松策略等于把 D11 删掉的那档换名重造 |
| **D4** | 角色 = **能力档的命名组合**;可组合性放在**范围**上,不放在能力上 | 排除了「自由勾选权限」——那是把「说不清的组合」外包给主人。范围只会收窄不会放大,所以任意组合都安全;能力自由组合不安全,因为「改策略 + 写代码」这类交叉项算不清。形状见 [`../ARCHITECTURE.md`](../ARCHITECTURE.md) §6 |

## 8. 待决策

⛔ 这些只有你能定。定之前不要往下反推架构 —— 否则架构会替你把它们默认掉,而
默认的方向必然是维持现状。

| # | 决策 | 选项与代价 |
|---|---|---|
| **D7** | 内置条件是给人拼的,还是只给机器生成用 | 决定 §5.2 是「把内置条件拆细」还是「承认自己写才是主路径」 |
| **D8** | 跨链策略是「一条策略 × 多条链」还是「每条链一条策略」 | 前者新增链只改一处,但「这条链上参数不一样」要另想办法 |
| **D9** | 出事时的最小动作 | 现在是「停掉一个 agent」。要不要有「整个工作区一键暂停」 |
| **D10** | 成员停用后,他名下钥匙签出的**在途**请求怎么办 | 全部作废:干净,但可能打断正在跑的合法任务。放行到结束:任务不断,但停用不是立即生效,与 G5 冲突 |

## 9. 不在范围内

⚠️ 明确写出来,免得被当成遗漏:

- **不做资产管理**:不负责换币、不负责路由、不给投资建议。
- **不做链上数据服务**:不承诺提供历史、行情、索引。
- **不替主人判断一笔交易划不划算**:只判断它**是否在授权范围内**。
